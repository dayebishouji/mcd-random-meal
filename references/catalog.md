# 餐品与套餐库

`menu-catalog.json` 是官方 MCP 的参考快照，供识别名称、规格、图片和每份营养使用，不替代实时菜单。2026-10-24 17:00:55起查询深圳福田高铁站餐厅、领展中心城餐厅、兴融二路（华融大厦）餐厅，菜单入口分别为101、115、100个。首店对50个单品候选查询详情，规范后46种单份、单一实物规格可参与抽取。多件实际组成、蘸酱和未知分类未加入。

每条记录保存实际菜单编码、默认实物组成、参考菜单价（分）、每份kcal（缺失为null）、官方图片、来源时间和门店。同编码在其他门店菜单出现只记为 `seen_menu_store_ids`；只有首店默认规格已验证，不声称逐店同规格。`request_item` 是首店当时的标准特调载荷，真实使用必须重新查询。

## “常见”与“常驻”

接口没有永久/常驻标记。39条 `common_reference=true` 是人工整理的常见参考候选，并非官方全年供应认证。月下相思扭扭薯、灰焰圆筒、龙焰鸡腿堡、高达吉士双牛堡、枫糖堡等7条本期/联名候选单独保留，不进新增的默认演示池；这不证明其余商品永久供应。

真实普通随机不按这份人工分类挑选：仍从本次门店可售的合规单品中等概率抽取。缓存不提供实时库存、会员优惠或全国最低价。

## 套餐与价格

`bundle-catalog.json` 收录首店32个套餐、随心配、单品精选等购买入口，保留实际轮次、必选份数、可选子项、默认选择、规格特调和 `diffPrice` 补差文案。父项菜单价不是换配后实付，不能直接把父项价与补差口算成官方整单报价。

12组具体购买方案在2026-10-24 17:10:21—17:10:27取得官方 `calculate-price` 回执，并对同样餐品另核单点。它们覆盖11种不同餐单（板烧搭配有两个等价入口），均满足主食最多1份、饮品最多1份、甜品最多1份。

例如双层吉士汉堡＋菠萝派，单点31.50元，随心配14.90元；那么大鸡排（椒盐风味）＋菠萝派，单点22.50元，随心配13.90元；麦香鸡＋中薯条＋“多汁柠柠”，单点43.00元，套餐28.50元。均是这家门店、这些规格、当次核价的历史记录，不能移用到其他饮品、大杯或今天/其他门店。

用户显式选择套餐模式时，程序重新查询模板涉及的当前菜单与套餐详情，匹配餐品、份数和特调后才进入候选。相同餐单去重，不按价格加权；选完后仍走完整单点、等价套餐和门店券核价。模板不是所有可配组合的穷举，报告说明比较范围。当前只有2–3样参考搭配，6样套餐请求不会自动变成双人餐或多汉堡。

## 离线演示

`examples/demo.json` 和 `docs/demo-data.js` 的抽签池由13样扩到42样：保留原13样虚构测试餐品及其历史/分享标识；新增29样名称、图片和已知营养来自常见参考候选，并排除与旧示意餐品对应的重复菜单入口。新增缺失营养仍为null。

新增11种套餐搭配参考，加上原4个虚构三件套入口，共15个套餐演示买法。演示金额与优惠是固定模拟，旧示意餐品不等同于真实核价规格，因此网页小票不作为官方回执。真实12组回执单独列出具体餐品、门店及时间。所有演示订单均不可用于下单。

餐品增多后，浏览器采用与Python相同的组合权重抽签，避免每次先枚举全部六样组合造成卡顿；普通随机概率仍不受价格、热量或套餐影响。
