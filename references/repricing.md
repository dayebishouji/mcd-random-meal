# 保留餐单，重新核价

当用户认可餐品但觉得贵时，重新核价已保存的餐单，不重新随机：

```text
python <SKILL_DIR>/scripts/main.py reprice --input <私有目录>/result.json --output <私有目录>/repriced.json --html <私有目录>/repriced.html
```

接受含 `meal` 的推荐结果或原始 `draw.json`。demo 输入只按虚构优惠重算，不连接 MCP；live 输入刷新同一家门店的菜单、规格、套餐/随心配详情和门店已有券，再逐方案整单核价。原 `meal`、`draw_id`、规格及份数不变，报价时间单独更新。默认规格或特调已改变、原餐品已不在当前菜单时停止，不把替代餐品当同一餐单。

先保留单点对照，再优先枚举能覆盖多样餐品的等价购买入口。套餐根据实际子项编码、份数和标准特调匹配，不能只看名称。可匹配一轮需选两样的入口；套餐父项数量限1。优惠券可以作用于当前可用的单品或套餐入口，每张券设置互斥组防止重复；能否组合最终由官方整单核价确认。

每轮最多检查60个套餐/随心配入口，每入口最多128组符合目标份数的子项组合，收集120个购买选项，枚举64份方案、搜索20000个节点。截断或失败必须展示。没找到更低报价时如实说明，不能重抽制造优惠。

## 外部平台券：独立参考

当前没有美团、抖音券的实时查询接口。根据用户提供的券面信息，填写私有 JSON，金额为整数分：

```json
{
  "draw_id": "从原餐单复制",
  "store_id": "从原餐单store.id复制",
  "context": {"orderType": 1, "beType": 1},
  "offers": [{
    "id": "user-voucher-1",
    "platform": "美团",
    "label": "用户提供的随心配参考",
    "purchase_fen": 1300,
    "extra_fen": 0,
    "covers": {"券面实际覆盖的餐单餐品id": 1},
    "conditions": "门店、有效期、规格、限购及补差条件；未知项明确写待核对",
    "confirmed": false
  }]
}
```

上面的13元只是用户提供的未验证参考，覆盖餐品是占位示例，不能原样用于真实餐单。根据券面逐项绑定同规格餐品；没有覆盖条件就先说明无法判断，不自行配对。`confirmed` 仅表示用户自行核对，不代表平台验证。

```text
python <SKILL_DIR>/scripts/main.py reprice --input <私有目录>/result.json --external-offers <私有目录>/external.json --output <私有目录>/reference.json --html <私有目录>/reference.html
```

每个选项分别计算 **购券价＋全部补差/费用＋余餐整单重新核价**，不是从菜单总价减券面折扣。余餐仍可使用其可用官方套餐或门店券，须由官方接口报价；完全覆盖时余餐为0，不额外发请求。余餐报价失败则不报合计。支持同时比较1–4个外部选项，各自独立，不自动叠加多张外部券。

输出的 `external_comparison` 与官方 `comparison` 分开。参考合计不是官方整单实付，平台券可能需独立购买/核销，不能保证可与官方订单叠加。不会购券、领券、开卡或下单。网页也提供这套手动参考流程，余餐为模拟数据；不把券备注写进分享链接或浏览器持久记录。
