# 连接检查与故障恢复

所有路径相对 Skill 目录；宿主执行时换成绝对路径。结果默认保存到不提交 Git 的 `local/`。

1. `python scripts/main.py doctor --offline`：检查安装和离线算法，报告凭据是否配置，不连接网络，也不输出凭据值。
2. 在本机私有环境配置 `MCD_MCP_TOKEN` 后，运行 `python scripts/main.py doctor`：检查 MCP 握手及门店、菜单、详情、营养、门店券、整单核价工具是否存在。
3. `python scripts/main.py live --city 深圳市 --keyword 福田 --count 1`：验证真实到店推荐。数量范围1–6，默认3；增加 `--no-main` 排除主食。首次未指定门店时使用接口返回的首家营业门店，不承诺最近。

| 情况 | 行为与恢复方式 |
|---|---|
| 未配置凭据 | 使用宿主已连接的 MCP，或在本机设置环境变量后运行 doctor；不要将凭据放入命令参数或聊天输出 |
| HTTP 401/403 | 不自动重试；到官方控制台检查凭据有效性和账号权限，更新后运行 doctor |
| HTTP 429 | 不自动重试；遵守官方限流提示，稍后再执行，不循环探测或换账号 |
| 超时、连接失败、HTTP 500/502/503/504 | 同一只读请求最多重试2次，间隔0.5和1秒；仍失败则停止，不能换成模拟结果 |
| 一个核价方案被业务规则拒绝 | 标记失败并继续其余已生成方案；不修改餐品、份数、规格或券参数来碰运气 |
| 某单品/套餐详情被拒绝 | 排除该入口并记录范围；网络/协议失败仍停止，不能把缺失详情当默认规格 |
| 门店券查询被拒绝 | 明示“券未验证”，仅比较其他可核价的购买方式，不说“账号无券” |
| 所有方案核价失败 | 不展示虚构实付价；检查连接及 schema 后，对保存的同一餐单重新准备与核价 |
| 营养或图片缺失 | 热量保留未知；图片使用占位，都不改变抽签概率 |
| 不足以满足单人餐数量 | 减少数量或更换门店；不通过多给饮品、甜品凑数，二者各最多1份 |

`call`、`quote`、`plan`、`compare` 可配合 `references/data-contract.md` 的文件流程，对已抽餐单继续工作。网络、鉴权或协议错误时保留已有有效报价并标出未核价范围。重新调用 `live` 会产生一次新抽取，不能把它当原餐单的重试；用户要求重抽时才重抽。

网络恢复只覆盖允许的只读工具，不创建订单、领券、兑换或支付。不通过轮换参数或账号尝试不支持的场景。
